# Урок 02. Как декомпилировать игру: от первой функции до Pull Request

[← К оглавлению](../README.md)

Этот урок — практический вход в матчинг-декомпиляцию на примере проектов для N64/GameCube/GBA. Принципы одинаковы для всех платформ.

## Что нужно знать заранее

| Навык | Уровень | Где подтянуть |
|---|---|---|
| C | уверенно: указатели, структуры, битовые операции | K&R, «Язык программирования C» |
| Ассемблер MIPS или PowerPC | читать, не писать | документация в вики проекта, справочники инструкций |
| Git | ветки, PR | любой базовый курс |
| Linux / WSL2 | командная строка | — |

Не нужно быть экспертом: многие участники учились прямо в процессе.

## Шаг 1. Выбери проект

| Проект | Платформа | Почему для новичка |
|---|---|---|
| [pret](https://github.com/pret) (pokeemerald, pokefirered, pokeheartgold) | GBA / DS | Огромное сообщество, подробные гайды |
| [zeldaret](https://github.com/zeldaret) (oot, mm, tp, tww, tmc) | N64 / GC / GBA | Отличная документация, много ревьюеров |
| [pmret/papermario](https://github.com/pmret/papermario) | N64 | Дружелюбное сообщество |
| [doldecomp](https://github.com/doldecomp) (melee и др.) | GameCube | Для знакомства с PowerPC |
| [Xeeynamo/sotn-decomp](https://github.com/Xeeynamo/sotn-decomp) | PS1 / PSP / Saturn | Несколько платформ одной игры |

У почти всех крупных проектов есть Discord-сервер: ссылка обычно в README.

## Шаг 2. Собери проект

```bash
# Ubuntu / WSL2: базовые пакеты (точный список — в README проекта)
sudo apt update
sudo apt install -y git build-essential python3 python3-pip binutils-mips-linux-gnu

git clone https://github.com/zeldaret/oot.git
cd oot
python3 -m pip install -r requirements.txt
# Положи СВОЙ ROM туда, куда указывает README, с нужным именем и версией
make setup
make -j"$(nproc)"
```

Если в конце видишь `OK` (или совпадение SHA-1) — ты собрал игру, идентичную оригиналу. Это обязательная отправная точка.

## Шаг 3. Найди функцию

Незадекомпилированные функции лежат в ассемблере, обычно в `asm/nonmatchings/...` и подключаются в C через макрос:

```c
#pragma GLOBAL_ASM("asm/nonmatchings/overlays/actors/ovl_En_Example/func_80A12345.s")
// или
INCLUDE_ASM("asm/nonmatchings/code/z_example", func_80012345);
```

Для первой задачи бери **короткую** функцию (10–40 инструкций) без сложных циклов. В некоторых проектах есть список «good first functions» или трекер в Discord.

## Шаг 4. decomp.me

1. Открой [decomp.me](https://decomp.me/) → **New scratch**.
2. Выбери платформу и пресет компилятора проекта (например, *Ocarina of Time*).
3. Вставь ассемблер функции и, если нужно, контекст (заголовки и структуры — в проектах есть скрипт `m2ctx.py`).
4. Нажми **Decompile** — m2c выдаст черновик на C.
5. Правь код, пока счётчик не дойдёт до **100%** (score 0).

## Шаг 5. Приёмы матчинга

| Симптом в диффе | Что попробовать |
|---|---|
| Перепутаны регистры | Порядок объявления переменных; временная переменная; объединить выражения |
| Лишний `move` | Убрать промежуточную переменную или наоборот добавить |
| `lh` вместо `lw` | Поменять тип поля: `s16` ↔ `s32` |
| Не тот порядок веток | Инвертировать `if`, поменять местами блоки, `else if` ↔ вложенный `if` |
| Цикл компилируется иначе | `for` ↔ `while` ↔ `do…while`; счётчик вверх/вниз; индекс ↔ указатель |
| Константа грузится иначе | `0x10` ↔ `16`, `float` ↔ `double`-литерал (`1.0f`) |
| Всё выглядит верно, но 99% | Проверь флаги компилятора для файла в Makefile; попробуй `static`/`inline` |

Главное правило: **сначала правильная логика, потом подгонка**. Не ставь странные конструкции, если не понимаешь, почему они нужны.

## Шаг 6. Перенеси в проект и проверь

```bash
# замени GLOBAL_ASM/INCLUDE_ASM на свой C-код, затем:
make -j"$(nproc)"
# хэш совпал — функция «заматчена»
python3 tools/asm-differ/diff.py -mwo func_80A12345   # если нужно отладить (путь зависит от проекта)
```

## Шаг 7. Документируй и отправь PR

- Дай функциям и переменным **осмысленные имена** (`EnExample_Update`, `this->timer`).
- Опиши поля структур, которые удалось понять.
- Следуй стилю проекта (часто есть `format.py` или clang-format).
- Создай Pull Request и будь готов к ревью: это нормально и полезно.

## Куда расти дальше

- **Документация**: даже без матчинга можно размечать структуры и переменные.
- **Инструменты**: splat, objdiff, decomp-toolkit, скрипты для проекта.
- **Порты**: когда декомпиляция близка к 100%, начинается работа над нативным портом.
- **Рекомпиляции**: изучи N64Recomp или XenonRecomp и попробуй рекомпилировать игру, у которой ещё нет проекта.
